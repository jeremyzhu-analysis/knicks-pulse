# Migration plan: Rust API + Vite frontend

Goal: replace the Node server with a Rust server (Axum) that owns the ESPN
sync, MySQL and every computed number, and serves the report as JSON. The
page is built with Vite and plain TypeScript, reusing the existing
rendering code in the browser. The MySQL schema and the numbers on the page
stay exactly as they are.

## Target stack

Versions are the newest stable releases published at least 7 days before
2026-11-02 (checked on crates.io and npm). Recheck them when `Cargo.toml` is
written.

| Crate / package | Version | Features | Used for |
| --- | --- | --- | --- |
| Rust toolchain | 1.99.1 | | `rust-toolchain.toml`; sqlx 0.9 needs at least 1.94 |
| tokio | 1.54.1 | `rt-multi-thread`, `macros`, `net`, `signal`, `time` | runtime, listener, sync timer, shutdown signals |
| axum | 0.8.9 | `http1`, `tokio`, no defaults | router, `/api/report` |
| tower-http | 0.7.1 | `fs`, `set-header` | serving `web/dist`, cache headers |
| sqlx | 0.9.0 | `mysql`, `mysql-rsa`, `runtime-tokio`, no defaults | pool, queries, transactions. The database is on localhost, so there's no TLS; `mysql-rsa` covers MySQL's `caching_sha2_password` full authentication without TLS |
| reqwest | 0.13.5 | `json`, `rustls`, no defaults | ESPN client |
| webpki-root-certs | 1.0.11 | | Mozilla's root certificates for the ESPN client (`tls_certs_only`), the same trust Node's bundled store gave. Unlike macOS's checker, it works inside the Claude Code sandbox, which blocks `trustd` |
| serde / serde_json | 1.0.229 / 1.0.154 | `derive` | ESPN JSON in, report JSON out |
| jiff | 0.2.38 | defaults (bundled tzdb) | UTC timestamps, New York calendar days |
| ts-rs | 12.0.1 | `serde-compat` (default) | generates the TS types for the API |
| anyhow | 1.0.104 | | application errors |
| vite (npm) | 8.3.5 | | frontend dev server and build |

Left out on purpose:
- **dotenvy**: its last release, 0.15.7, was in March 2023. `.env` is a few `KEY=value` lines, so `config.rs` reads it with a
  ~15-line loader: skip blank lines and `#` comments, split at the first `=`,
  and never override a variable that is already set (the same rule as
  `process.loadEnvFile`).
- **chrono**: sqlx 0.9 has no jiff feature. Rather than run two date crates,
  queries move DATETIME values as UTC strings
  (`DATE_FORMAT(starts_at, '%Y-%m-%dT%H:%i:%sZ')` out,
  `'YYYY-MM-DD HH:MM:SS'` in) and jiff parses them.
- **regex**: the two patterns (`OFF_FLOOR_PLAY` and the round-name cleanup)
  become plain string checks.
- **thiserror**, **clap**: there's a single error type (the ESPN HTTP status)
  and three subcommands, so `std::env::args` covers them.
- **tracing**: the server prints three kinds of lines (listening, sync
  progress, errors), as the Node version did with `console.log`; `println!`
  and `eprintln!` cover them.

## API shape

`GET /api/report` returns one `Report`. It is the current `Report` minus
what the browser doesn't need, plus the results that `page.ts` computes
today by calling into `compute.ts`:

- `Game` in the API has no `plays`, `players`, `us` or `them`. It keeps `id`,
  `startsAt` (ISO string), `home`, `opponent`, `venue`, `note`, `periods`,
  `pts`, `oppPts`, `usByPeriod` and `themByPeriod`. `latestGame` adds
  `topScorer: { fullName, pts } | null`.
- New top-level fields `quarters`, `factors` and `situations`: the results of
  `quarters()`, `factors()` and `situations()` for the current season against
  last season, or `null` where `page.ts` renders nothing today.
- `impact` becomes `{ kind, tone }`, where `kind` is a string union
  (`"lowMinutes" | "lineupDrag" | "twoWay" | ...`). The label and the title
  sentence are built in TS from `kind` and fields already on `PlayerRow`.
  Text formatting stays in one language, and Rust's `{:.1}` doesn't have to
  match JS's `toFixed`, whose rounding of exact ties differs.
- `current` and `lastRegular` become `currentKey` and `lastRegularKey`, the
  keys of entries in `seasons`, so the JSON doesn't carry those seasons
  twice. The frontend looks them up.
- `won()` and `margin()` stay as one-line TS helpers.
- Counts are `i32` and derived values `f64`. No `i64`/`u64` reaches the API,
  because ts-rs types them as `bigint` while `JSON.parse` returns `number`.
  Game ids stay strings.

The Rust server keeps the serialized JSON as `Arc<Bytes>` and builds it again
only after a sync that stored games. If the build fails, the cache is left
empty so the next request tries again, which is the same rule as
`currentPage()` today.

## Traps the port must keep

Each of these changes a number on the page if it's ported naively:

1. **Order of iteration.** JS `Map` keeps insertion order. Player rows are
   sorted by minutes with a stable sort, so ties keep first-appearance order.
   Lineup and floor totals are summed in insertion order. Use a `Vec` plus a
   `HashMap` index (or keep the order explicitly), not a bare `HashMap`.
2. **Float sums.** Sum in the same order as the TS `reduce`. Rust's
   `iter().sum()` on `f64` also sums left to right, so the results should
   match exactly.
3. **`parseInt` semantics.** `int()` in `espn.ts` parses a leading sign and
   digits ("+5" → 5, "12abc" → 12, "" → 0). `madeAttempted` and `parseClock`
   build on it. Port this behavior, not `str::parse`.
4. **ESPN dates have no seconds** (`2025-10-22T23:30Z`). Parse that form
   explicitly and cover it with a unit test.
5. **`clock_s` is `DECIMAL(5,1)`.** Read it as `CAST(clock_s AS DOUBLE)` so
   no decimal crate is needed.
6. **IN lists.** sqlx doesn't expand `IN (?)` for arrays. The load queries
   become `WHERE game_id IN (SELECT id FROM games WHERE home_team_id = ? OR
   away_team_id = ?)`. The sync's stored-ids check reads `SELECT id FROM
   games`. Bulk inserts use `QueryBuilder::push_values`.
7. **Retries.** ESPN requests retry up to 3 attempts on 5xx, waiting 1 s and
   then 2 s. A 404 on a summary skips that game. Keep this as an
   `EspnHttpError { status }` that `sync.rs` checks with `downcast_ref`.
8. **Rest days** count calendar days in `America/New_York`
   (`jiff::Zoned::date()`), not UTC days.
9. **Optional where Node never looks.** serde rejects a missing field
   anywhere in the JSON, but Node only fails on the fields it reads. ESPN
   lists players who didn't play without an id or name (game 401810680), so
   athlete fields are optional and only required once a player has played.
10. **Unordered queries.** Node's player query had no `ORDER BY`, and its row
    order breaks ties (sorting by minutes, the top scorer). MySQL returned it
    in `(game_id, player_id)` order through the `game_players_team` index; the
    Rust query states that order. `clock_s` is read with `CAST(... AS CHAR)`
    and parsed in Rust, which gives the same double as JavaScript's `Number()`.
11. **One sync at a time.** The timer task runs each sync inline and uses
   `MissedTickBehavior::Skip`, so syncs never overlap.

## Steps

Each step ends with a check against the running Node app. Comparison scripts
live in the session scratchpad, not in the repo, and are deleted at the end.

### 0. Prerequisites and baseline

- **Sandbox:** `cargo` and `rustc` currently fail with "operation not
  permitted" because `~/.cargo` and `~/.rustup` aren't readable from the
  session. The settings need read access to both folders and write access
  to `~/.cargo/registry` and `~/.cargo/git`. I'll draft the settings change
  in the scratchpad for you to apply.
- Add `rust-toolchain.toml` with channel `1.99.1`. You run `rustup` once if
  that version isn't installed.
- Baseline: a scratchpad script (`baseline/dump.mts`) imports the existing
  modules. From a single database read, it writes `baseline.html`
  (`renderPage()`, the same string `GET /` returns), `baseline.json` (the
  report in the API shape above) and `db-state.json` (game count and latest
  `synced_at`). It doesn't start the Node server, because the server syncs on
  startup even with `SYNC_INTERVAL_MINUTES=0`. Nothing syncs into `knicks`
  until step 3 has been checked; before diffing, `db-state.json` confirms the
  data hasn't changed.

### 1. Cargo project, config, database, `migrate`

- `Cargo.toml` with the pins above, `main.rs` subcommands, `config.rs` (env
  plus the `.env` loader, same names and defaults), `db.rs` (pool of 5,
  `time_zone '+00:00'`). `.env` is read from the current directory; Node read
  it relative to the source files. The README must say to run from the repo
  root. Each step adds only the crates it uses.
- `migrate` creates the database if needed, then runs
  `include_str!("../db/schema.sql")` with `sqlx::raw_sql`.
- Check: run `migrate` against a fresh database `knicks_rs` and compare
  `SHOW CREATE TABLE` for all seven tables with `knicks`.

### 2. ESPN client and `sync`

- Port `espn.ts` with serde structs: `Option` and `#[serde(default)]` wherever
  the TS uses `?.` or `??`. Port `sync.ts`: one transaction per game, the
  same upserts, delete then insert, and `synced_at = UTC_TIMESTAMP()`.
- Unit tests for `int`, `madeAttempted`, `parseClock` and the ESPN date form.
- Check: the Node sync fills a fresh `knicks_node` and the Rust sync fills
  `knicks_rs`, minutes apart, so ESPN corrections to old games can't look
  like porting bugs. Compare every table in both directions with `EXCEPT`,
  ignoring `synced_at`, and use the `performance_schema` digest check from
  the recipes to confirm no statement errored. sqlx adds `PIPES_AS_CONCAT`
  and `NO_ENGINE_SUBSTITUTION` to the session `sql_mode`; no query here
  uses `||`, so it makes no difference.

### 3. Report in Rust

- Port `load.ts`, `lineups.ts` and `compute.ts`, plus `seasonLabel`,
  `lastName` and `dayNumber` from `format.ts`. Then write `api.rs`, which maps
  the result to the API shape.
- `cargo test` exports the TS bindings into `web/src/api`.
- Check: add a temporary `knicks report-json` subcommand, or call the handler
  from a test, and diff its output against `baseline.json`. Numbers must be
  equal; any difference is a porting bug until shown otherwise. Then run
  Node and Rust on a copy of the data altered to reach the rarer branches
  (replays rejected, broken lineups, the "Rebounding" label, a playoff game
  with no note) and diff those outputs too. Remove the temporary subcommand
  afterwards.

### 4. Server

- `server.rs`: `GET /api/report` (`cache-control: no-cache`, plain-text 500
  "Something went wrong." on failure), and `ServeDir` for `web/dist` as the
  fallback service. Hashed files under `/assets/` get
  `max-age=31536000, immutable`; `index.html` gets `no-cache`. Axum and
  ServeDir handle HEAD and answer 405 for other methods.
- On start: bind `HOST:PORT`, run one sync in the background, then start the
  timer if `SYNC_INTERVAL_MINUTES > 0`. On SIGINT/SIGTERM: stop the timer,
  shut down gracefully, close the pool.
- Check: run the binary from a scratch folder holding a stand-in
  `web/dist`, against `knicks_rs`. `curl` every route: GET and HEAD (with
  `curl -I`; `-X HEAD` waits for a body), POST and DELETE (405 with
  `Allow: GET,HEAD`), unknown paths (404 "Not found"), and the cache header
  on each. Diff `/api/report` against the Node report on the same database.
  Then delete a game, confirm the cached report still has it, let a
  1-minute sync store it again, and confirm the next report is rebuilt.
  Send SIGTERM from the same shell that started the server, since the
  sandbox blocks signals across commands, and expect exit code 0.
- ServeDir sends `text/html` without a charset (Node sent
  `charset=utf-8`), so `index.html` must declare `<meta charset="utf-8">`.

### 5. Frontend

- Copy `render/`, the display half of `format.ts` and `styles.css` to
  `web/src/` (the originals go in step 6; the baseline script imports them).
  They read the new `Report` fields instead of calling `compute.ts`, take the
  ISO date strings, and build the impact label and title from `kind`
  (`render/impact.ts`). `renderPage` becomes `renderBody` (header, main,
  footer). The API also sends `replayTolerance` and `pairMinSeconds`, so the
  page text never restates server thresholds.
- `index.html` is only the shell. `main.ts` fetches `/api/report`, writes
  the body, then attaches the season-switch and tooltip handlers that
  `public/app.js` attached. If the fetch fails, it shows "Something went
  wrong."
- `web/vite.config.ts`: `server.proxy` sends `/api` to
  `http://127.0.0.1:3000`; `vite web` makes `web/` the root and builds to
  `web/dist`.
- `package.json`: adds `vite`, `dev` (`vite web`), `build` (`vite build web`)
  and a `typecheck` that also runs `tsc -p web`. `mysql2`, `@types/node` and
  the Node scripts stay until step 6, because the comparison helpers use
  them. You run `npm install` after the manifest changes.
- Check: serve the built page from the Rust server against `knicks_page`
  (an exact copy of `knicks`, with ESPN left blocked so the startup sync
  fails without writing). Serve `baseline.html` with the old CSS and
  `app.js` next to it, and load both in Playwright's headless shell at
  1280 px and 390 px. The header, main and footer HTML must be identical,
  and so must the screenshots, after load, after a season switch and after
  a pairing click. Repeat through `npm run dev`. Single-process Chromium
  holds one page at a time, so run the scenarios one after the other.
  - The sticky header of the per-game quarter table can differ by a few
    hundred pixels between two screenshots of the *same* page after a click;
    compare the old page with itself before treating that as a regression.
  - Vite's CSS minifier rewrites some syntax (`background: none` →
    `0 0`, `max-width` media query → range form) without changing meaning.

### 6. Cutover and cleanup

- Delete `src/*.ts`, `src/report/`, `src/render/` (now under `web/`),
  `public/`, the root `tsconfig.json` (replaced by `web/tsconfig.json`) and
  the scratchpad scripts. Drop the `knicks_rs` database.
- Update `README.md` (Stack, Setup, Layout, the `npm run` commands, the
  `node:http` line). Search the repo for `npm start`, `npm run sync`,
  `npm run migrate`, `node:http`, `mysql2`, `Node runs the TypeScript` and
  `.nvmrc`, and fix every hit. `.nvmrc` stays, because Vite still runs on
  Node.
- Remove `mysql2`, `@types/node` and the `start`/`migrate`/`sync` scripts
  from `package.json`; `typecheck` becomes `tsc -p web`. Drop the
  `knicks_node`, `knicks_rs` and `knicks_page` databases first, while the
  SQL helper still has `mysql2`.
- Run `cargo fmt`, `cargo clippy` and `npm run typecheck` once at the end.
  The repo has no TS linter or formatter, and none gets added.

## Open choices (defaults in bold)

- **Runtime-checked queries (`query_as` + `#[derive(FromRow)]`)**, or sqlx's
  compile-time `query!` macros. The macros need a running database or a
  committed `.sqlx/` cache plus `sqlx-cli` on every build. With about ten
  queries, all covered by the step 2 and 3 comparisons, runtime checking is
  enough.
- **Serve `web/dist` from disk, relative to the repo root**, or embed it in
  the binary (needs a crate such as `rust-embed`). Embedding only matters if
  the binary gets deployed somewhere else.
